# 寄售订单分次付款

新建及尚未生效寄售订单继续沿用管理员审批流程；生效时按整张订单金额建立应收。未付余额 = 当前有效应收（含已记录的人工应收调整）− 已核实并分配到本单的付款。仓库发货不再增加应收，付款也不会重复创建订单。未生效订单不产生债务。

财务、管理员、责任销售以及所属经销商在订单详情查看同一份“分次付款记录”：第一次、第二次等付款的银行实际到账日期、本次抵扣金额、累计已抵扣金额及尚未付清金额。按实际到账日期排列，单笔到账多次分配给同一订单时合并显示一笔，避免把分配操作数当付款次数。期初预存款独立注明为抵扣，没有实际到账日期时不虚构日期。银行账户和银行参考号不会通过此明细向销售及经销商公开。打开详情及“刷新付款记录”均读取最新数据。

经销商或销售可上传各次付款水单、日期和申报金额；待核实申报单独列出，不扣减余额。财务或管理员可在详情点击“核实本单到账”，或核实关联本单的付款凭证。记录银行实际金额、日期、账户和唯一参考号后，系统自动将可抵扣金额分配到该寄售订单，超额部分保留为该经销商预存款。实际金额可与申报不同，以核实值为准。仍可使用原有“分配实收”功能；未分配到账不减少本单欠款。

整单结算的寄售库存报售时必须关联原寄售订单；确认只扣寄售库存，不重复创建销售订单、应收或付款。按原订单及所在地的库存流水校验数量；该地点中已整单结算的库存不能绕过关联转成历史报售应收。历史未关联寄售库存仍按旧报售流程结算。

升级不自动重记历史已生效、按报售结算的发货单，避免对已生成的结算单重复收费；这些订单在详情注明历史口径。尚未生效订单审批后使用新规则。历史应收、实收、分配和附件均保留。

涉及已抵扣付款的撤单、退款和应收调整仍遵守既有财务约束，银行实收和分配流水保持追加记录。仓库退货不自动冲销应收，应由管理员据实登记应收调整。

## 新建订单时一次上传多笔付款

销售或管理员选择“寄售”后，可点击“增加一次付款”填写第 1、2、3 次等付款。每笔独立包含已付款金额、实际付款日期、对应水单，以及选填交易参考号。尚未付款可以留空；开始填写的记录须同时提供日期、正数金额及附件。付款计划继续填写到期日或备注，实际付款日期不允许填写未来日期。每次最多 20 笔，每个附件 PNG/JPEG/PDF 不超过 5MB，一次合计不超过 10MB；后续仍可在订单详情补传。

订单和全部付款申报在同一事务内保存。任意一笔无效则整次提交失败，不留下半张订单或孤立附件。相同幂等键重试不会重复生成订单或付款记录；改变日期、金额、附件后使用原幂等键会拒绝。修订未生效的寄售订单保留已有凭证，表单仅追加新记录。

订单详情和财务付款申报列表显示每笔申报日期、金额、核实状态及对应水单；核实弹窗保留同一笔信息供银行核对。已核实凭证仍保留可查，银行实际到账日期和金额独立记录。寄售订单须先按原有管理员审批流程生效，财务或管理员才可核实本单款项；上传凭证本身不使订单生效，也不改变实收、欠款或预存款。撤销、拒绝或过期的寄售订单不接受追加凭证及核实入账。
