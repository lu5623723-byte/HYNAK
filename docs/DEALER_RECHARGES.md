# 经销商充值与账户余额

“经销商充值”面向管理员、财务、销售及经销商。经销商只查看本人账户，销售只查看所负责经销商；管理员及财务可选择经销商。

## 入账与匹配

- 经销商、销售或管理员填写金额、付款日期并上传 PNG/JPEG/PDF 充值水单，不关联订单。申报提交后为待核实，不增加余额。重复提交使用幂等键，避免重复生成申报和附件。
- 财务或管理员独立核对银行，填写实际金额、实际日期、真实账户和唯一银行参考号。实际金额可不同于申报。支持直接登记未有申报的真实充值到账，也可填写原因退回不匹配的申报。已退回申报不能再核实。
- 核实充值后启用该经销商的余额自动匹配：先按付款到期日升序、订单编号升序抵扣已生效且未结清的订单，金额不足时只部分抵扣，余额不允许为负。剩余款留在经销商账户，新订单生效时继续自动抵扣。存量已核实且未占用的余额、核实期初预存款也参与匹配。
- 已核实但属于某张尚未生效银行转账现付单的款项继续为原单占用；不能被其他订单重复消费。原单按原有足额到账规则生效并分配后，超额部分才成为可用余额。
- 所有自动分配都在现有事务写锁下追加到账/分配/审核日志。幂等重试、同一银行参考号、同一充值申报以及并发余额下单不会重复入账或超额抵扣。原有财务/管理员手动“分配实收”功能保留。

## 余额下单

现付订单可选择“银行转账”或“账户余额”。银行转账沿用付款时间、水单及财务核实流程。选择账户余额时不再要求重复转账或上传同一笔钱的水单；先抵扣已有生效欠款，再检查余额是否足额覆盖新订单。足额且价格审批完成则自动生效、建立应收并核销；不足时保持未生效，等待充值补足。销售自定义价仍须管理员批准，充值不绕过价格审核。余额付款订单未生效时不能另行上传订单银行付款申报，应通过充值补足。

## 余额与明细

账户展示可用余额、累计核实入账、累计订单抵扣及待处理占用。账户明细记录银行充值/普通到账/期初预存款的入账，自动或手工分配对应的订单及金额，以及账面余额；账面余额包含待处理占用，可用余额不包含占用。未核实充值不计入任何已核实余额。充值申报、核实实际金额及附件可追溯，销售和经销商不通过余额明细获得真实收款账户或内部银行参考号。

原寄售订单的“分次付款记录”也展示充值款匹配到该单的实际到账日期和本单抵扣金额，同一笔到账多次分配至同一订单合并成一次付款。实际到账日期与分配记录时间分别保留。

## 升级

Schema 9 新增独立充值申报表、到账关联字段、订单付款方式和经销商自动匹配开关；历史订单默认银行转账、历史自动匹配默认关闭，不改写旧实收和分配。第一次核实充值或选择余额下单会启用自动匹配。数据库及充值附件一并沿用现有备份恢复。
