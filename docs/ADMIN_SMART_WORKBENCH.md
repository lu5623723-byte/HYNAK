# 管理员智能工作台

后续扩展：所有角色现已使用职责化工作台，见[五角色智能工作台](ROLE_SMART_WORKBENCHES.md)。下文描述最初管理员版本及其验收记录；旧管理员专用接口保持兼容。

入口：管理员“业务概览”，位于日期指标下方。按已有业务数据自动生成分级提醒、来源依据、负责角色和下一步建议，所有入口只打开原有页面或详情；提醒本身不审批订单、不核实银行到账、不调拨库存，也不修改信用评级。

本版采用可解释规则，本机可直接运行，不依赖OpenAI密钥，不向外部AI服务上传业务数据。政策AI助手仍使用独立配置和管理员确认流程。没有把规则分析称为模型预测，也不自动作出授信或其他财务决定。

## 提醒覆盖

| 事项 | 依据与处理 |
|---|---|
| 管理员审核、现付财务核实 | 当前订单状态、创建日期、对应待核实水单；创建达到阈值时提高优先级。日期表示订单创建时间，不冒充进入该审核阶段的时间。现付核实责任仍是财务。 |
| 草稿、客户确认、过期报价 | 已创建达到阈值且流程仍未完成，提示销售核对资料与确认情况。 |
| 付款到期、实际逾期欠款 | 仅有效状态订单的实际未付余额；未核实截图不减欠款。今日到期不计逾期，圣保罗次日才计逾期。 |
| 生效订单付款凭证 | 只提示待核实凭证，标明申报金额，不把截图视为实收。 |
| 余额付款与充值 | 余额订单按已核实可用余额核对；原待审银行款的占用金额不当作可用余额。待核实充值独立标为申报；已有余额和欠款并存时提示核对抵扣归属。 |
| 商品及赠品缺货 | 合并全部当前生效待发订单需求，扣除已有锁货，再与未锁定可用库存比较；同批库存不会重复分给多个订单，零价赠品也计入待发。 |
| 跨仓待调拨 | 汇总一级/二级仓可覆盖整单，但没有单个仓可覆盖全部SKU时提示仓管核对调拨。部分出库仍走原授权流程。 |
| 低库存、负库存 | 只用一级/二级仓，寄售点不当作可售仓库库存。停售商品不产生低库存提醒；账面负数独立提示核对实物和原流水。 |
| 锁货即将到期 | 尚无已核实并分配到本单的实收，且有效锁货进入提醒窗口；按订单合并。已抵扣部分实收时不发“未收款到期”提醒。 |
| 信用评级 | 已有自动评级C/D，展示暂评标志和当前逾期依据；无可靠历史的N级不会当作差评。只建议查看依据和跟进。 |
| 提货、车辆编号异常 | 待提货出库单达到天数阈值，或已登记缺少车辆编号说明；已交付/撤销单不产生待提货提醒。 |
| 寄售报售 | 当前待处理报售，提示核对原单与数量，沿用防止重复应收的规则。 |
| 政策即将结束 | 已启用且尚未结束的政策进入提醒窗口，提示管理员准备新政策。 |

缺货公式：全局未锁定待发需求 − 全部一级/二级仓的未锁定可用库存，低于零时取零。展示全局需求、已锁定数量、可用数量和相关订单。判断单仓整单可发时，将本单自己的有效锁货加回单仓可用量，避免把自己的锁货误当成他人占用。已部分付款、仍有效的锁货即使原72小时期限已过也保持原业务处理。

## 筛选与口径

- 默认分析全部当前业务，避免本月的“生效日期”筛选隐藏待审核订单或更早欠款。
- 可选择“订单跟随上方已应用筛选”：订单提醒使用原dashboard的日期口径、日期范围、经销商、销售、类型、状态及付款状态。经销商提醒按经销商/销售范围；其余额与评级仍为当前值。
- 库存、锁货竞争需求及政策期限始终使用当前全局情况，页面有明确说明。选择部分订单不会让系统忽略其他订单对同一批库存的需求。
- 支持按优先级、事项类型及订单/经销商/SKU关键词筛选；每页12条。提醒条数不等于订单笔数；逾期金额只加总一次每张逾期订单，不重复加信用风险等提醒的金额。
- 结果显示分析时间和实际采用的范围。更新失败保留上次结果，并显示失败状态，不把失败视作“没有风险”。

## 可调整阈值

| 规则 | 默认值 | 范围 |
|---|---:|---:|
| 逾期高优先级天数 | 7天 | 1–90天 |
| 订单/充值创建后升级天数 | 2天 | 1–30天 |
| 低库存提醒（可用量≤阈值） | 5台 | 0–1000台 |
| 付款到期提前提醒 | 3天 | 0–30天 |
| 待提货提醒 | 3天 | 1–30天 |
| 锁货到期提前提醒 | 24小时 | 1–72小时 |
| 政策结束提前提醒 | 7天 | 1–60天 |

规则和展示偏好按管理员账号保存在当前浏览器，属于个人管理视角，不改变系统业务规则或其他账号权限。支持恢复默认。编辑规则或有未应用修改时暂缓自动同步，应用后恢复；提醒数据沿用页面30秒自动刷新、回到页面刷新及手动重新分析机制。

## 权限与验证

`GET /api/admin/insights` 由后端限定管理员，销售、财务、仓管和经销商均不可读取管理员全局报告。提醒按钮沿用原订单、评级、库存、寄售和财务页面；所有业务写入仍由原后端权限控制。数据来自现有共享数据库，不创建另一套独立业务记录。无新增数据库结构。

自动测试使用独立临时数据库，覆盖未核实款与真实欠款区别、逾期金额去重、圣保罗到期日、赠品与竞争需求、锁货、跨仓调拨、寄售库存排除、信用暂评、待交付、配置范围、其他角色403、审批后提醒消失，以及分析前后订单/库存/实收/分配等数据不变。

本地网页验证仅查看和修改个人提醒偏好；未创建或确认真实订单、银行交易、出入库或销售政策。本次不包含阿里云部署更新。

2026-11-02 验收：406项Python回归测试及20组前端检查通过，其中27项为本工作台专项。浏览器验证识别8条测试业务待办、优先级/类别/关键词过滤、原订单详情入口、按已应用日期范围切换、阈值调整及刷新后保存、规则编辑期间保护，以及重新分析后保留展开的数据依据。验收结束恢复全部当前业务和默认阈值，保留管理员工作台页面。
