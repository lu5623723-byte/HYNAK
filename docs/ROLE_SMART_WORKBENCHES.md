# 五角色智能工作台

2026-11-02：在各账号“业务概览”中提供按职责划分的工作台，共用现有订单、付款、余额、库存和交付记录。

| 角色 | 主要事项 | 主要指标 |
|---|---|---|
| 管理员 | 价格与订单审批、资金核对、库存协调、信用、政策期限、交付和佣金 | 高优先级、全部待办、实际逾期欠款、待核实充值申报、全局待发缺口 |
| 销售 | 责任客户的审批跟进、付款资料、客户确认、供货协调、信用和本人佣金 | 高优先级、全部待办、责任订单逾期欠款、待客户确认订单、供货协调事项 |
| 财务 | 现付到账审核、充值核实、申报金额差异、未分配余额、到期欠款、回款跟进和佣金结算 | 高优先级、全部待办、待核实现付订单、待核实充值申报、实际逾期欠款 |
| 仓管 | 生效订单待出库、商品与赠品缺口、低/负库存、调拨、锁货、车辆编号、提货及报售 | 高优先级、全部待办、待出库订单、待发台数（含赠品）、当前缺口 |
| 经销商 | 自己采购的审核与付款进度、到期付款、充值余额、提货、评级和本人寄售点 | 高优先级、全部待办、我的订单尚欠、我的可用余额、待提货出库单 |

每条提醒提供优先级、原因、数据依据、负责角色、下一步建议和原业务页面入口。销售的审批与佣金提醒使用“跟进/查看进度”，经销商使用“查看自己的采购/付款/联系责任销售”，不提供越权审批、核款或结算操作。仓管业务概览使用待出库表、待提货表与库存快览，不显示通用财务指标和销售排名。

## 数据范围与权限

- `GET /api/insights` 从登录会话取得角色，不采信查询参数指定的角色。先使用 `snapshot(db, actor)` 按原权限读取数据，再分析；不在完整管理员报告上事后隐藏字段。
- 管理员查看全局；销售只分析责任经销商和订单、本人佣金；经销商只分析自己名下数据和寄售点。财务、仓管沿用既有业务可见范围。
- 销售的供货分析只汇总责任订单的未锁定需求，并使用扣除全部锁货后的可用库存，不返回其他客户订单编号或未锁定需求。其他客户的需求竞争由仓管统筹；管理员和仓管继续使用全局待发需求。
- 仓管工作台报告的金额为 `null`，数据依据采用数量/库存/交付字段白名单；汇总不含实收、充值和欠款金额。此限制针对新工作台报告，不改写原订单详情权限。
- 提醒入口只做页面导航或打开详情，仍由原业务接口校验每次写入权限。保留管理员专用旧接口 `GET /api/admin/insights`，其他角色访问仍为403。
- 分析不审批、不核款、不改价、不调拨、不修改信用或佣金状态。佣金结算条件发生变化时显示人工复核提示。

## 筛选、规则与更新

默认查看职责范围内全部当前待办，避免本月生效日期筛选漏掉待审订单或旧欠款。可切换“订单跟随上方已应用筛选”，联动既有自定义起止日期、日期口径及业务筛选。库存、余额、评级等当前值在界面中明确注明。

支持优先级、事项类型、关键词和分页。各角色只显示相应的提醒规则字段；偏好按当前账号保存在当前浏览器。修改个人提醒阈值不改变业务到期日或审批权限。自动同步沿用30秒、恢复页面显示及手动刷新机制；有未保存表单或规则修改时暂缓刷新。切换账号或角色后不复用上一角色的报告。

## 新增判断口径

- 待出库台数包含付费商品和赠品的剩余数量；只分析当前有效且未全部出库订单。
- 待提货单在实际交付后移出待办；已有超期/车辆编号异常提醒的出库单不再重复生成普通提货提醒。
- 现付差额 = 待核实申报合计与“订单总额 − 已核实且关联本单申报的银行入账”的差异。正常分次付款不冒充错误，仅提示人工核对，不重复计入已核实金额。
- 回款跟进按同一经销商/订单最新一条约定日期判断，已付清不再提醒。
- 经销商寄售点库存提醒只使用自己名下、在售商品的地点数据，不把其他经销商或普通仓库库存变为自己的库存。

本版使用可解释规则自动分析，不需要OpenAI密钥、不向外部模型发送业务数据。已有AI政策助手保持独立配置和管理员确认发布流程。
